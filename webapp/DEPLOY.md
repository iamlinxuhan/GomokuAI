# 网页版：从源码到哔哩哔哩 Toy 上线

面向：维护这个仓库的人。目标是把 `webapp/` 打成 Toy 平台能吃的一个 zip，
发出去之后能得到 `https://www.bilibili.com/toy/<slug>/` 这样一个地址。

---

## 一、这套东西是怎么拼起来的

| 文件 | 来源 | 说明 |
|---|---|---|
| `gomoku-free.js` / `gomoku-ban.js` | `cpp/web/build_wasm.sh` | 同一份 C++ 内核，`#if GOMOKU_BAN` 分出有禁手与无禁手两份，各含内联的 wasm |
| `engine-worker.js` | 手写 | 在 Worker 里加载上面两份之一，同时兼作"没有 Worker 时"的主线程退路 |
| `book.js` | `tools/build_book_web.py` | `opening_book.py` 那张表的明文版：局面 → 开局着法。桌面版 `ai_move` 的第二道闸门，网页版少了它入门档会明显变弱 |
| `app.js` / `style.css` / `index.html` | 手写 | 棋盘、难度、禁手提示、悔棋、复盘、联机，全部是浏览器这边新写的 |

桌面版和网页版共用 `cpp/src/` 里的 `Board` / `Engine` / `tables` / `ban` ——
棋力不是另写一份，是同一份内核换个壳。禁止改动任何一处：

- 一切资源用**相对路径**（`./app.js`）。Toy 把作品挂在子路径下，根绝对路径会白屏。
- `index.html` 未压缩必须 ≤ 1 MB，整包 ≤ 50 MB（本包目前 index.html 约 8 KB，
  zip 约 149 KB）。
- 交付目录必须**扁平**：`index.html` 就在 zip 根上，引擎文件与 Worker 同级
  —— Worker 里的 `importScripts('./gomoku-ban.js')` 按 Worker 自己的 URL 解析。

---

## 二、出包

首次准备 emscripten（只需一次）：

```sh
git clone https://github.com/emscripten-core/emsdk.git ~/emsdk
cd ~/emsdk && ./emsdk install 3.1.69 && ./emsdk activate 3.1.69
```

以后每次出包就两条命令，在仓库根目录执行：

```sh
source ~/emsdk/emsdk_env.sh
sh cpp/web/build_wasm.sh          # 编 wasm → webapp/dist/gomoku-{free,ban}.js
sh webapp/make_dist.sh            # 拷页面文件 + 打 zip → webapp/gomoku-web.zip
```

`make_dist.sh` 会自己检查两个硬门槛（`index.html` ≤ 1 MB、整包 ≤ 50 MB），
超了直接报错退出，不会给你一个传上去才炸的包。

只改了 JS/CSS 没动 C++ 的话，跳过 `build_wasm.sh`，直接跑 `make_dist.sh`。

**改了开局库才需要多跑一步**（`opening_book.py` 或建库脚本 `tools/build_book.py`）：

```sh
uv run --frozen python tools/build_book_web.py   # → webapp/book.js
```

`book.js` 是生成物，和 `opening_book.py` 一样不许手改 —— 两边的键格式不同
（那边是 Zobrist 哈希，这边是明文局面），手改必然只改对一边。忘了重建时
`make_dist.sh` 会直接报"缺少 webapp/book.js"，不会悄悄发出一个没有开局库的包；
"文件在但是旧的"由 `tests/test_book_web.py` 盯着（它把生成器重算一遍再逐字节
比对），跑一次 `pytest -q tests/test_book_web.py` 就知道。

## 三、本地先跑一遍

```sh
cd webapp/dist && python3 -m http.server 8000
# 浏览器开 http://127.0.0.1:8000/
```

必须用本地服务，不能双击 `index.html`：`file://` 下 Chrome 不让构造 Worker。
（真双击也能玩，会退到主线程，思考时页面卡住，状态栏会注明。）

建议检查：

- 手机视口（DevTools 里切 iPhone 尺寸）下棋盘不变形、按钮点得到；
- 选「禁手」执黑，下一手 3-3，看得到红圈叉标记，点下去先弹确认；
- 选「宗师」下一手，思考中点「悔棋」应当**立刻**回到上一手（这是掐 Worker 的效果）。
- 面板上的主题胶囊（「当前主题(点击以切换)」）切深色：卡片、面板、按钮全部
  跟着变，**木盘不变色**（棋盘色是两套主题共享的，见 `app.js` 顶部色表）。
  选择记在 localStorage，下次打开直接用深色 —— 恢复主题的那三行 `<script>`
  在 `index.html` 的 `<head>` 里、样式表之前，挪到 `app.js` 里会让卡片先画
  一帧浅色再渐变过去。
- 选「入门」、执黑下天元：AI 应当**立刻**落在 K10（(9,10)），读数写
  `开局库 d9`。这一手不搜索，来自 `book.js`；和桌面版同一档的应手逐格相同。
  要是它回了天元斜下方的 (7,7)，说明开局库没生效。
- 下完一局 → 终局遮罩点「📊 复盘」→ 选一档强度 → 列表里**每一手都在**，
  点任意一行，棋盘换成那一手落子前的局面（幽灵子＝当时下的，红圈＝引擎推荐）。
  人机局里 AI 的着法不进列表。
- 联机：开两个标签页，一个「创建房间」拿到 6 位房间码，另一个把码填进
  「房间码」点「加入房间」（或直接打开 `?room=<码>` 的链接）。房主那边会弹
  「玩家XXXX 想上桌」，点「同意上桌」后他执白。第三个人再进来只能观战，
  棋盘只读、没有座位。联机里**悔棋按钮是收起的**，重开只有房主能点。

## 四、传到 Toy

1. 打开 `https://www.bilibili.com/toy/publish`（登录自己的账号）。
2. 上传 `webapp/gomoku-web.zip`。**不要再套一层目录**，zip 里直接是
   `index.html`、`app.js`、`style.css`、`engine-worker.js`、`book.js`、
   `gomoku-*.js` 七个文件。
3. 填作品信息：
   - **slug**：建议 `gomoku-ai`。只用 `[A-Za-z0-9_-]`，**发布后不可修改**，
     它就是最终地址 `bilibili.com/toy/gomoku-ai/` 的那一段。
   - **封面**：4:3，用 `~/视频/GomokuAI-推广/gomoku-ai-cover-toy-1200x900.png`
     （已有 1200×900，是从 4:3 封面等比缩的，不是裁的）。
   - **简介**：可以直接抄下面这段——
     > 19 路五子棋，C++ 引擎编译成 WebAssembly 在你本地算棋，六档难度，
     > 有 RIF 禁手规则与悔棋，打完了还能逐手复盘。想和朋友下就开个房间，
     > 把 6 位房间码发过去。人机的全部计算都在浏览器里完成，不排队。
4. 提交审核。审核通过之前只有你（或白名单）能看到预览地址。

> 平台各字段的叫法与校验规则可能随版本变化，页面上的提示以它为准；
> 官方说明在 `https://www.bilibili.com/toy/publish/sdk/skill`。

## 五、联机怎么走（没有服务器）

B 站 Toy 没有实时通道（SDK 里只有按玩家隔离的云存档），所以联机不去额外部署，
而是页面里直连**公共消息中转 ntfy**：`https://ntfy.sh`，CORS 全开、不用注册。
收走 SSE（`EventSource`），发走普通的 `fetch` POST。房间里没有任何服务端，
Toy 那边也不需要申请什么权限。

- **主题名 = `gomoku-<6 位房间码>`**。房间码是唯一的钥匙：知道这 6 位的人都能
  进，先被房主同意的那位执白，其余只能观战。
- **权威在房主**。房主落子直接改本地局面，然后把**整盘**（361 格 + 落点序列）
  广播出去；加入方落子只发一个 `move` 意向，房主校验后代为落地再广播。
  加入方的盘面永远是从房主动作里抄来的，所以两边不会各走各的。
- **消息**：`hello`（敲门）、`admit` / `deny`（房主答复座位）、`state`（权威局面，
  带自增 `rev`，旧的一律丢）、`move`（加入方意向）、`sync`（要一次完整局面）、
  `bye`。加入方每次 SSE 重连都会重发 `hello` + `sync`，所以断线不用手工重连。
- **限制**：中转是公共 topic，消息会在公共缓存里留约 12 小时 —— 别拿它传隐私
  内容。整盘约 3 KB（361 子下满时），在 ntfy 的单条上限之内。
- **连不上时**：状态行写「联机服务连不上，正在重试…」，EventSource 自己重连；
  人机对战完全不受影响（用的是本机 wasm，与网络无关）。

## 六、发布之后要改东西

改完源码重新 `sh webapp/make_dist.sh`，回到 Toy 的后台重新上传 zip 走一次审核。
**slug 不会变**，所以老链接一直有效。如果这次改了棋力参数（难度表、搜索参数），
记得同步 `engine.py` 的 `DIFFICULTY` —— 桌面版与网页版共用同一张表，两张表
一分叉，"同一档"就成了空话。

## 七、排错

| 现象 | 多半是什么 |
|---|---|
| 白屏，控制台 404 `/app.js` | 资源写成了根绝对路径；检查 `index.html` 里的 `./` |
| 上传报 `307000` | `index.html` 超过 1 MB —— 多半是有人把 wasm 内联进了 HTML |
| 棋盘能显示，落子没反应 | Worker 没起来。看控制台有没有 `gomoku-*.js` 的 404；`#ban` / `#free` 片段写错也会这样 |
| 落子后页面卡十几秒 | 说明退到了主线程（`file://` 或平台禁 Worker）。面板「引擎」一行会写成 `C++ · WASM（主线程）`，鼠标悬停有说明；棋力不受影响 |
| 禁手点不显示 | 检查是否选了「禁手」规则，以及是不是轮到了白方 —— 白方不受禁手约束 |
| 入门档开局回 (7,7)、读数不是 `开局库 d9` | `book.js` 没打进去（控制台有 404），或者选的是禁手规则 —— 那张表只在无禁手规则下有效 |
| 提示「联机服务连不上，正在重试…」 | 连不上 `ntfy.sh`（有些公司网/地区会挡）。EventSource 会自己重连；人机对战完全不受影响 |
| 联机里点了棋盘没反应 | 先看回合：没轮到你、座位还没被房主同意、或者上一手还在等房主确认，都不收子 |
| 联机两边棋盘对不上 | 加入方刷新一次页面即可 —— 重新连上会先发 `sync` 把房主的整盘要回来。房主是唯一权威 |

## 八、验过什么、没验什么

**验过的**（免得以后重复花时间）：

1. **逻辑**：node + 假 DOM + 真 wasm，106 项断言，Worker 与主线程两条路径各跑一遍
   —— 对局、AI 应手、悔棋（含"思考中悔棋 1 ms 内回退"）、五连与斜五连、3-3 禁手
   标记、禁手确认后判负、执白时 AI 开局天元、主题胶囊、`to_grid` 的接受域，
   以及复盘（只收自己的手、空盘起始手不评分、分值差非负、点行回看落子前的局面）
   与联机协议（房主就地落子并广播、加入方只发意向、观战收不到子、旧序号丢弃、
   重启后由 `sync` 收敛）。中转在测试里是两个桩，真实的 ntfy 没在 CI 里连过。
   用的是仓库里的 `webapp/t_webapp.js`，打完包直接跑：

   ```sh
   node webapp/t_webapp.js                # Worker 路径
   FALLBACK=1 node webapp/t_webapp.js     # 主线程退路
   ```
2. **棋力与桌面版同源**，分三层钉住：
   - 开局：入门档天元之后应回 (9,10)，读数 `开局库 d9` —— 与
     `engine.ai_move(board, 2, 1)` 的实测输出（`reason='开局库'`, `best_val=-380`,
     `depth=9`）逐项相同；
   - 前三手整条开局（(9,10) → (10,10) → (8,10)）与桌面版逐格相同；
   - 中局：三个 12–16 子的局面在 wasm 与 C++ 上给出**同着、同分、同深度**
     （节点数差 1%，是置换表预热），说明搜索本身没有第二份实现。
3. **视觉**：`firefox-esr --headless --screenshot` 逐张看过四种尺寸 × 两套主题
   （1200×900 / 1400×1000 / 1920×1080 / 400×860），选择页、对局页、窄屏堆叠都
   对过。棋盘是按 `board_render.py` 重画的：木纹、内嵌面、九星、跳 I 的坐标、
   最后一手环，与桌面版同源。

**还没验的**：

0. **联机在真机两端没对过。** 协议、权威归属、重连后的 `sync` 都在 node 里用
   桩验过；两台真实设备经 `ntfy.sh` 对局的端到端（尤其国内网络的连通性、
   SSE 被中间设备截断后的重连）没有实测。
1. **Toy 平台允不允许 Web Worker 未知。** 不允许也不会白屏（自动退到主线程，
   面板「引擎」一行会注明），但每手思考期间页面会卡住。
2. **移动端的触摸手感没试过。** 落子判定用的是 `click` 而不是 `touchend`，
   间距按半格放宽过；实机上如果觉得不跟手，改 `app.js` 的 `onBoardClick`。
3. **真机上的帧率没量过。** 木纹是启动时生成一次 512² 贴图的，之后每帧只是
   `drawImage` + 棋子；按理说不是瓶颈，但没在低端手机上压过。
